# История изменений

## 1.0.0 — 2026-10-20

- Зафиксирован контракт прототипа: расчёт TLE/GP JSON в WGS84 и реестр метаданных КА.
  README содержит quick start, пошаговый гайд Swagger/curl и разбор типовых ошибок.
- Удалён счётчик версии токенов и отдельная модель для него. Новая миграция сохраняет
  пользователей и реестр; токены 0.3.x требуют повторного входа после обновления.
- Крайние даты с переполнением при переводе в UTC возвращают полевую ошибку `422`.
  Задача создания миграции корректно передаёт описания с пробелами.
- Health-проба больше не занимает ёмкость расчётов и не вызывает ложный `503`;
  число незавершённых проб остаётся ограниченным.
- Бенчмарки включают предел 100000 точек. В Docker сравниваются порции 512/1024/4096
  и один/два вычислителя; результаты и основания настройки сохранены в документации.
- Проверены 128 тестов, чистый запуск Compose и сохранение данных при перезапуске.
  CI дополнительно отправляет оба документированных примера через настоящий HTTP-сервер.

## 0.3.2 — 2026-10-20

- Создание демонстрационного пользователя перенесено в `poetry run poe add-test-user`.
  Удалены `dev/`, `scripts/`, настройки `APP_DEV_*` и тест отдельной демоконфигурации.
- Окружение запускается стандартным Docker Compose после копирования `.env.example`.
  Пример настроек содержит фиксированный демонстрационный ключ; автоматическая генерация удалена.
- Проверки задачи Poe выполняются на тестовой PostgreSQL; документация тестирования
  описывает текущую реализацию, история этапов сохраняется в Git и changelog.

## 0.3.1 — 2026-10-20

- Вместо CLI и отдельного менеджера пользователей добавлена подготовка демоданных
  в `dev/project_user.py`, запускаемая через `python -m dev.main`.
- `start-local.sh` автоматически создаёт `testuser / test-password`; логин и пароль
  настраиваются через `APP_DEV_*`. Повторный запуск сохраняет существующую запись,
  в том числе при одновременной подготовке.
- Пример входа Swagger заполнен демоданными. Обновлены инструкции и интеграционные тесты;
  схема БД и формат пользовательских токенов сохранены.

## 0.3.0 — 2026-10-20

- Добавлен общий реестр КА: создание, чтение, полная замена, удаление, страницы по NORAD ID.
- Таблицы спутников и пользователей добавлены новой автогенерированной миграцией;
  уникальность проверяется PostgreSQL, конфликты API возвращают `409`.
- Добавлены вход по логину/паролю, Argon2id, короткие JWT, CLI создания пользователя,
  смены пароля с отзывом токенов и отключения учётной записи.
- Расчёт и реестр требуют Bearer-токена. Redis атомарно считает квоты входа и пользователей;
  превышение даёт `429` с `Retry-After`, отказ лимитера закрывает операции через `503`.
- Readiness проверяет PostgreSQL, Redis и вычислительный пул. Проверки паролей ограничены
  по параллельности и не блокируют HTTP-поток; недоверенные proxy headers отключены.
- Локальный скрипт запуска генерирует секрет вне Git. Обновлены Swagger, Compose, CI,
  HTTP-бенчмарк и объяснения контрактов и альтернатив.
- Добавлены проверки реальных транзакций реестра, входа, отзыва доступа, конкурентных
  запросов к Redis, истечения окна и отказов; тестовые БД и Redis изолированы.

## 0.2.1 — 2026-10-20

- Исправлены примеры Swagger: TLE и CelesTrak GP JSON можно выполнить без ручного
  заполнения. Тесты сверяют их с документированными запросами и отправляют через реальный пул.
- Добавлены `OrbitCalculator` и `CalculationWorker` с явным владением шкалой времени
  и конфигурацией одного вычислителя на процесс.
- `CalculationResult` переведён на Pydantic и перенесён в `models/pydantic/calculations.py`.
- Модели отчётов вынесены в `models/pydantic/benchmarks.py`, чтение настроек —
  в `benchmarks/settings.py`. Формат отчёта и названия переменных окружения сохранены.
- Численный алгоритм и внешний контракт расчёта сохранены.

## 0.2.0 — 2026-10-20

- Добавлен `POST /api/v1/orbits/coordinates`: TLE и CelesTrak GP JSON, UTC-сетка,
  SGP4 и геодезические координаты WGS84 с высотой в километрах.
- Реализованы ограниченный пул процессов, прогрев, порции векторизации, тайм-ауты,
  отказ при перегрузке и сохранение занятого места при отмене ожидания.
- Готовность проверяет PostgreSQL и вычислительный пул; занятость пула не считается отказом.
- Добавлены численные контрольные тесты, проверки контрактов, реального пула и его аварии.
- Сохранены данные CelesTrak с источниками, готовые примеры запросов и объяснение контракта.
- Добавлены воспроизводимые замеры ядра/HTTP и настройки `APP_COMPUTE_*`, `APP_BENCH_*`.
  По первым замерам выбран размер порции 1024 точки.
- Исправлена сериализация ошибок входа с NaN/Infinity и переполненными числами:
  API возвращает 422 с типизированным описанием поля.
- Исходные байты CelesTrak сохраняются атрибутами Git и проверяются по SHA-256.

Реестр метаданных КА запланирован на 0.3.0.

## 0.1.0 — 2026-10-20

- Добавлены каркас FastAPI, health API, типизированные настройки и JSON-логи.
- Реализованы управляемый lifecycle ресурсов и асинхронные транзакции PostgreSQL.
- Добавлены Alembic и начальная миграция, Docker-образы приложения и тестов, Docker Compose.
- Настроены Poetry, Ruff, ty, pre-commit и GitHub Actions.
- Добавлены unit-тесты и интеграционные тесты на отдельной PostgreSQL.
- Зафиксированы причины архитектурных решений, объяснение предметной области,
  настройки и порядок проверки.

Расчёт орбит запланирован на 0.2.0, реестр КА — на 0.3.0.
