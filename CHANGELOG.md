# История изменений

## 1.2.2 — 2026-10-21

- Добавлена лицензия MIT с уведомлением об авторских правах `2026 IgorYatsenko`.
- Лицензия указана в метаданных проекта и README; файл `LICENSE` включён
  в Python-пакет и Docker-образ приложения.

## 1.2.1 — 2026-10-21

- Неположительное среднее движение в TLE возвращает `422 invalid_orbit`.
  NUL и некорректный Unicode в метаданных отклоняются до обращения к PostgreSQL.
- Лимит точек проверяет менеджер расчёта; HTTP-преобразование ошибок собрано
  в общих обработчиках. Исключения сгруппированы по назначению.
- Временная недоступность БД отличается от внутренних ошибок: соответственно
  `503 database_unavailable` и `500 internal_error`. Диагностика не раскрывает SQL и параметры.
- Добавлено обнаружение просроченных расчётов через `APP_COMPUTE_STALL_TIMEOUT_SEC`.
  Пул становится неготовым и не принимает новые задачи, не завершая текущие процессы;
  после завершения просроченных задач готовность восстанавливается.
- HTTP-замеры сохраняют тайм-ауты и сетевые ошибки, продолжают остальные попытки
  и записывают частичный отчёт при исключении или Ctrl+C.
- Quick start извлекает токен внутри контейнера; Poetry на хосте для него не требуется.
  Добавлены регрессионные тесты и уточнены контракты и эксплуатационные ограничения.
- Прошли 145 модульных и 39 интеграционных тестов, в том числе полный набор
  в свежем Docker-образе; проверены штатная сборка, quick start и HTTP-блок CI.

## 1.2.0 — 2026-10-21

- Сервис Auth владеет проверкой паролей и выпуском/проверкой токенов.
  Менеджеры используют его прикладные операции; отдельный модуль токенов удалён.
- Добавлены минимальные метрики Prometheus: количество и длительность HTTP-запросов
  по методу, шаблону маршрута и статусу. Содержимое запросов в метки не попадает.
- `/metrics` доступен без токена и пользовательской квоты; сбор отключается настройкой.
  При нескольких HTTP-процессах метрики суммируются, временные файлы очищаются при остановке.
- Проверены 119 модульных и 33 интеграционных теста, включая настоящий HTTP-сервер
  с одним и двумя процессами и сохранение доступа к метрикам при исчерпанной квоте.

## 1.1.0 — 2026-10-21

- Код создания демонстрационного пользователя вынесен в `api/demo_user.py`.
  Poe ссылается на функцию; quick start и CI запускают её внутри контейнера.
  Для демонстрационного запуска достаточно Docker с Compose.
- Добавлены четыре независимые контрольные точки WGS84 из опубликованных векторов
  Vallado, преобразованных через Astropy и IERS-B. Описаны источники, версии,
  воспроизведение и допуски; тесты используют готовые значения.
- Предел расчёта увеличен до 200000 точек; сценарии замеров включают двое суток
  с шагом 1 секунда. Все ограничения по-прежнему задаются через `APP_COMPUTE_*`.
- По результатам HTTP-замеров ожидание расчёта увеличено до 60 секунд,
  срок ожидания клиента benchmark — до 90. Отчёты сохраняют код ошибки,
  различая занятость пула и тайм-аут; оба сценария покрыты тестами.
- Полный набор из 138 тестов прошёл в Docker. Проверены чистый запуск,
  создание демопользователя в контейнере и границы нового лимита через HTTP.

## 1.0.1 — 2026-10-20

- `/health/ready` возвращает пустой ответ: `200` при готовности всех ресурсов,
  `503` при отказе или исключении любой проверки.
- Общий хаб проверяет тот же список ресурсов, который запускает и останавливает:
  PostgreSQL, Redis, сервис паролей и вычислительный пул. Удалены отдельный
  менеджер готовности и модель его JSON-ответа; диагностика отказов остаётся в логах.
- Обновлены документация, OpenAPI и HTTP-проверка CI под пустой ответ готовности.
- Прошли 102 модульных и 29 интеграционных тестов на отдельной тестовой инфраструктуре.

## 1.0.0 — 2026-10-20

- Зафиксирован контракт прототипа: расчёт TLE/GP JSON в WGS84 и реестр метаданных КА.
  README содержит quick start, пошаговый гайд Swagger/curl и разбор типовых ошибок.
- Удалён счётчик версии токенов и отдельная модель для него. Новая миграция сохраняет
  пользователей и реестр; токены 0.3.x требуют повторного входа после обновления.
- Крайние даты с переполнением при переводе в UTC возвращают полевую ошибку `422`.
  Задача создания миграции корректно передаёт описания с пробелами.
- Health-проба больше не занимает ёмкость расчётов и не вызывает ложный `503`;
  число незавершённых проб остаётся ограниченным.
- Бенчмарки включают предел 100000 точек. В Docker сравниваются порции 512/1024/4096
  и один/два вычислителя; результаты и основания настройки сохранены в документации.
- Проверены 128 тестов, чистый запуск Compose и сохранение данных при перезапуске.
  CI дополнительно отправляет оба документированных примера через настоящий HTTP-сервер.

## 0.3.1 — 2026-10-20

- Вместо CLI и отдельного менеджера пользователей добавлена подготовка демоданных
  в `dev/project_user.py`, запускаемая через `python -m dev.main`.

## 0.3.0 — 2026-10-20

- Добавлен общий реестр КА: создание, чтение, полная замена, удаление, страницы по NORAD ID.
- Таблицы спутников и пользователей добавлены новой автогенерированной миграцией;
  уникальность проверяется PostgreSQL, конфликты API возвращают `409`.
- Добавлены вход по логину/паролю, Argon2id, короткие JWT, CLI создания пользователя,
  смены пароля с отзывом токенов и отключения учётной записи.
- Расчёт и реестр требуют Bearer-токена. Redis атомарно считает квоты входа и пользователей;
  превышение даёт `429` с `Retry-After`, отказ лимитера закрывает операции через `503`.
- Readiness проверяет PostgreSQL, Redis и вычислительный пул. Проверки паролей ограничены
  по параллельности и не блокируют HTTP-поток; недоверенные proxy headers отключены.
- Локальный скрипт запуска генерирует секрет вне Git. Обновлены Swagger, Compose, CI,
  HTTP-бенчмарк и объяснения контрактов и альтернатив.
- Добавлены проверки реальных транзакций реестра, входа, отзыва доступа, конкурентных
  запросов к Redis, истечения окна и отказов; тестовые БД и Redis изолированы.

## 0.2.0 — 2026-10-20

- Добавлен `POST /api/v1/orbits/coordinates`: TLE и CelesTrak GP JSON, UTC-сетка,
  SGP4 и геодезические координаты WGS84 с высотой в километрах.
- Реализованы ограниченный пул процессов, прогрев, порции векторизации, тайм-ауты,
  отказ при перегрузке и сохранение занятого места при отмене ожидания.
- Готовность проверяет PostgreSQL и вычислительный пул; занятость пула не считается отказом.
- Добавлены численные контрольные тесты, проверки контрактов, реального пула и его аварии.
- Сохранены данные CelesTrak с источниками, готовые примеры запросов и объяснение контракта.
- Добавлены воспроизводимые замеры ядра/HTTP и настройки `APP_COMPUTE_*`, `APP_BENCH_*`.
  По первым замерам выбран размер порции 1024 точки.
- Исправлена сериализация ошибок входа с NaN/Infinity и переполненными числами:
  API возвращает 422 с типизированным описанием поля.
- Исходные байты CelesTrak сохраняются атрибутами Git и проверяются по SHA-256.

Реестр метаданных КА запланирован на 0.3.0.
