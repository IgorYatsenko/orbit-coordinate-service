# Предметная область без предварительной подготовки

Здесь объяснена используемая модель расчёта.
Документ фиксирует смысл выбранных терминов и помогает объяснить решение на защите.

## Что именно нужно вычислить

КА — космический аппарат. Он движется по орбите, поэтому вопрос «где находится аппарат»
обязательно должен содержать время. В нашем API клиент задаст описание орбиты, начало,
конец и шаг, а сервис вычислит положение для каждой точки получившейся временной сетки.

Орбитальные элементы — параметры модели движения: наклон орбиты, её форма, ориентация,
положение аппарата на орбите и другие параметры. Это исходные данные для алгоритма,
а не готовая последовательность координат.

## TLE, GP и OMM

TLE означает Two-Line Element Set — набор элементов в двух строках фиксированного формата.
Положение символа имеет значение; пробелы внутри строки нельзя произвольно удалять.
Иногда перед двумя строками находится название аппарата: такой текст часто называют 3LE.
Название не является третьей строкой орбитальных параметров.

GP означает General Perturbations — семейство данных и моделей с учётом возмущений движения.
CelesTrak публикует такие данные в нескольких представлениях.

OMM означает Orbit Mean-Elements Message — сообщение со средними орбитальными элементами.
Формат CelesTrak GP JSON использует названия и смысл полей OMM. Он удобен для нашего API:
вместо разбора позиций символов видны именованные значения. Полный стандарт OMM также имеет
другие представления, например XML; они в согласованный объём входных форматов не входят.

Следовательно, «поддержать JSON» означает поддержать конкретную структуру CelesTrak,
а не любой набор чисел с названием «орбита». В ней известны единицы, система времени
и модель, для которой предназначены элементы.

## Основные поля JSON

| Поле | Смысл |
| --- | --- |
| `NORAD_CAT_ID` | Номер объекта в каталоге; используется для идентификации КА |
| `OBJECT_NAME` | Название объекта |
| `OBJECT_ID` | Международное обозначение, связанное с запуском; полная дата запуска из него не следует |
| `EPOCH` | Момент времени, к которому относятся элементы |
| `INCLINATION` | Наклон плоскости орбиты к экватору, градусы |
| `ECCENTRICITY` | Мера вытянутости орбиты; безразмерная величина |
| `RA_OF_ASC_NODE` | Ориентация плоскости орбиты, градусы |
| `ARG_OF_PERICENTER` | Ориентация ближайшей к Земле части орбиты внутри её плоскости, градусы |
| `MEAN_ANOMALY` | Угловой параметр положения аппарата вдоль модельной орбиты, градусы |
| `MEAN_MOTION` | Среднее число оборотов за сутки |
| `BSTAR` | Параметр модели сопротивления атмосферы, используемый SGP4 |

Единицы важны: перепутанные градусы и радианы или обороты в сутки и в минуту могут дать
формально численный, но неверный результат. Преобразование выполняется адаптером библиотеки,
а тесты проверят конкретные значения на границах.

NORAD — сокращение названия North American Aerospace Defense Command.
Для сервиса важна роль каталожного номера как идентификатора, а не устройство этой организации.
Классический числовой TLE ограничен пятью позициями для номера; современный JSON поддерживает
более длинные номера. Поэтому модель реестра не получит ограничение `99999`.

Некоторые поля CelesTrak не передаёт, поскольку их значения подразумеваются для этого источника:
центр `EARTH`, система координат `TEME`, время `UTC`, теория элементов `SGP4`.
Это документированное свойство формата. Адаптер сможет применять эти значения именно для
согласованного формата CelesTrak; явно несовместимые значения должны завершаться ошибкой.

Источник: [форматы GP CelesTrak](https://celestrak.org/NORAD/documentation/gp-data-formats.php).

## Эпоха и дата запуска

Эпоха — момент, относительно которого описана орбита. Новые наблюдения позволяют построить
новый набор элементов с новой эпохой для того же аппарата.
Например, один и тот же спутник мог быть запущен много лет назад, а текущие элементы описывают
его орбиту около сегодняшней даты.

Из этого следуют два независимых поля: эпоха набора орбитальных данных и дата запуска КА.
Заполнить дату запуска эпохой было бы фактической ошибкой.
В GP JSON дата запуска отсутствует; каталог SATCAT содержит отдельное поле `LAUNCH_DATE`.
В нашем реестре клиент передаст её явно, когда она известна.

Источник: [описание SATCAT](https://celestrak.org/satcat/satcat-format.php).

## Что делает SGP4

SGP4 означает Simplified General Perturbations 4. Это алгоритм распространения орбиты:
он принимает согласованные с ним элементы и вычисляет положение в заданный момент.
«Распространение» здесь означает перенос модельного состояния по времени, вперёд или назад.

Элементы TLE являются средними элементами специальной модели. Простая формула движения
по идеальному эллипсу с теми же числами не воспроизведёт результат SGP4.
Поэтому используем готовую проверенную реализацию `sgp4` через библиотеку Skyfield.
Собственная реализация потребовала бы отдельной верификации большого численного алгоритма.

SGP4 сначала возвращает пространственный вектор в TEME (True Equator, Mean Equinox).
Это связанная с ориентацией Земли система, которая не вращается вместе с поверхностью как
обычная географическая сетка. Её `x, y, z` нельзя непосредственно выдать как широту и долготу.
Следующий шаг учитывает время и вращение Земли и преобразует вектор в географическое положение.
Эту часть выполняет Skyfield.

Источники: [описание sgp4](https://pypi.org/project/sgp4/),
[спутники в Skyfield](https://rhodesmill.org/skyfield/earth-satellites.html).

## Почему одновременно WGS72 и WGS84

WGS означает World Geodetic System — мировую геодезическую систему.
В этом решении названия относятся к двум разным задачам.

1. При расчёте движения SGP4 использует набор гравитационных констант.
   Для стандартных TLE библиотека рекомендует WGS72: элементы обычно построены с этими константами.
2. Для выдачи географического положения используется эллипсоид WGS84 — согласованная
   математическая поверхность Земли. На неё опирается требуемая широта, долгота и высота.

Таким образом, требование вернуть WGS84 выполняется на этапе преобразования результата.
Оно не требует менять гравитационные константы, с которыми были построены исходные элементы.

Источник: раздел Gravity в [документации sgp4](https://pypi.org/project/sgp4/).

## Смысл результата

- Широта — геодезическая широта WGS84 в градусах, от −90 до +90.
- Долгота — угол в градусах; восточное направление положительное, диапазон `[-180, 180)`.
- Высота — расстояние над эллипсоидом WGS84 в километрах.

Эллипсоид — гладкая модель формы Земли. Он не повторяет горы, рельеф и поверхность океана.
Поэтому высота аппарата над эллипсоидом и его расстояние до местного грунта — разные величины.
Задание требует первую; цифровая модель рельефа для неё не нужна.
При использовании Skyfield нужно брать высоту аппарата, а не высоту точки на поверхности под ним.

## Время и сетка

UTC — Coordinated Universal Time, согласованная шкала времени для обмена данными.
Дата API должна содержать смещение или `Z`, например `2026-10-20T12:00:00Z`.
Сервис приводит разные смещения к UTC. Указанная в формате CelesTrak `EPOCH` без смещения
трактуется как UTC по контракту этого источника.

Точки формируются как `start + k × step`, пока значение не превышает `end`.
За сутки с шагом 1 секунда получится 86 401 точка, поскольку обе границы входят в сетку.
С шагом 60 секунд — 1 441 точка. Если конец не попадает на сетку, последний неполный шаг
не добавляется: иначе расстояние между последними точками отличалось бы от заказанного.

## Точность и ошибки

Численная корректность программы и точность знания реальной орбиты проверяются по-разному.
Можно убедиться, что программа воспроизводит эталон алгоритма, но это не доказывает,
что старые исходные элементы описывают сегодняшнее движение аппарата.
На реальное движение влияют сопротивление атмосферы, манёвры и другие факторы.
По мере удаления от эпохи достоверность обычно ухудшается; универсальной гарантии на произвольный
интервал исходное задание и выбранные данные не дают.

Расчёт разрешён в обе стороны от эпохи. Клиент увидит её в ответе и сможет оценить актуальность входа.
Автоматическое получение новых элементов изменило бы воспроизводимость запроса, поэтому исходные
данные выбирает клиент.

При некоторых состояниях библиотека возвращает ошибку распространения или нечисловой результат.
`NaN` (Not a Number — «не число») и бесконечность не должны попадать в успешный ответ.
По согласованному контракту ошибка хотя бы одной точки завершает весь запрос ошибкой с указанием времени.

Численные тесты отдельно проверяют эталонные векторы SGP4, преобразование координат,
единицы, временную сетку и эквивалентность TLE/JSON с учётом точности представления.
Четыре контрольные точки широты, долготы и высоты получены из опубликованных векторов
отдельной библиотекой Astropy. Сравнение с ними проверяет всю цепочку перехода от TLE
к WGS84. Происхождение значений и допуски описаны в [данных тестов](../tests/fixtures/README.md).
Одинаковый спутник и близкие эпохи ещё не означают, что два опубликованных набора элементов идентичны.

Источник ограничений: [Earth Satellites — Skyfield](https://rhodesmill.org/skyfield/earth-satellites.html).
