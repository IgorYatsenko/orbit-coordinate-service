# Настройки 1.2.0

Все эксплуатационные настройки начинаются с `APP_`. Подгруппы обозначают владельца:
`APP_DB_*` — соединения приложения с БД, `APP_TEST_DB_*` — отдельная тестовая БД,
`APP_COMPUTE_*` — вычислительные процессы, `APP_BENCH_*` — ручные замеры,
`APP_DEPLOY_*` — сборка и публикация контейнеров.
`APP_AUTH_*` управляет паролями и токенами, `APP_REDIS_*` подключением лимитера,
`APP_RATE_LIMIT_*` квотами, `APP_TEST_REDIS_*` отдельным Redis тестов,
`APP_METRICS_*` экспортом HTTP-метрик.

Python читает `.env` в текущем рабочем каталоге. Переменные окружения процесса имеют приоритет
над `.env`, затем используются defaults. `get_settings()` кэширует проверенную конфигурацию
на время жизни процесса: после изменения настройки приложение нужно перезапустить.
Неверный порт, размер пула или timeout приводят к ошибке конфигурации при запуске.

Compose также читает `.env` для подстановок. В контейнерах приложения он явно устанавливает
`APP_DB_HOST=postgres` и `APP_DB_PORT=5432`, поскольку там используется внутренняя сеть Docker.
Снаружи эта же БД доступна через `localhost:APP_DB_PORT`, по умолчанию `55432`.
Это два адреса одного контейнера, предназначенные для разных мест подключения.

## Приложение

| Переменная | Default | Назначение |
| --- | --- | --- |
| `APP_HOST` | `0.0.0.0` | Адрес прослушивания HTTP внутри процесса |
| `APP_PORT` | `8000` | Порт HTTP; в Compose также порт публикации |
| `APP_ROOT_PATH` | пустая строка | Внешний префикс reverse proxy; сам маршруты не перемещает |
| `APP_LOG_LEVEL` | `INFO` | `DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL` |
| `APP_DOCS_ENABLED` | `true` | Доступность `/docs` и `/openapi.json` |
| `APP_HTTP_WORKERS` | `1` | Число HTTP-процессов; у каждого собственные DB- и вычислительный пулы |
| `APP_HTTP_TRUSTED_PROXY_IPS` | пустая строка | Доверенные IP/CIDR reverse proxy через запятую; пустое значение отключает обработку proxy headers |
| `APP_HTTP_KEEP_ALIVE_SEC` | `5` | Срок удержания неактивного HTTP-соединения |
| `APP_SHUTDOWN_TIMEOUT_SEC` | `15` | Время ожидания HTTP-запросов при остановке |

В Compose `APP_HOST` должен позволять вход из сети контейнера, обычно `0.0.0.0`.
Доступ с хоста ограничивается отдельным `APP_DEPLOY_BIND_HOST`.
`APP_ROOT_PATH` нужен, если reverse proxy публикует сервис под дополнительным URL-префиксом.

## Метрики Prometheus

| Переменная | Default | Назначение |
| --- | --- | --- |
| `APP_METRICS_ENABLED` | `true` | Сбор HTTP-метрик и открытый `/metrics`; при `false` endpoint возвращает `404` |
| `APP_METRICS_HTTP_BUCKETS_SEC` | `[0.01,0.05,0.1,0.25,0.5,1,2.5,5,10,30,60]` | Границы гистограммы времени ответа в секундах; JSON-массив конечных положительных чисел, строго по возрастанию |

Запуск через `python -m api` или `poe start` при нескольких HTTP-процессах подготавливает
общий временный каталог метрик. Внутренняя `PROMETHEUS_MULTIPROC_DIR` задаётся адаптером
библиотеки автоматически и не является отдельной пользовательской настройкой.
Границы метрик одинаковы у всех процессов одного запуска. Подробнее: [метрики](architecture.md#12-метрики-prometheus).

## PostgreSQL приложения

| Переменная | Default | Назначение |
| --- | --- | --- |
| `APP_DB_HOST` | `localhost` | Хост при запуске Python локально; в Compose переопределяется |
| `APP_DB_PORT` | `55432` | Порт при запуске Python локально и порт публикации БД |
| `APP_DB_USER` | `orbits` | Имя пользователя |
| `APP_DB_PASSWORD` | `orbits` | Локальный демонстрационный пароль |
| `APP_DB_NAME` | `orbits` | Имя БД |
| `APP_DB_POOL_SIZE` | `5` | Максимум постоянных соединений на HTTP-процесс |
| `APP_DB_MAX_OVERFLOW` | `0` | Дополнительные временные соединения на процесс |
| `APP_DB_POOL_TIMEOUT_SEC` | `5` | Ожидание свободного соединения |
| `APP_DB_CONNECT_TIMEOUT_SEC` | `5` | Установление нового соединения |
| `APP_DB_STATEMENT_TIMEOUT_SEC` | `5` | Выполнение SQL на стороне PostgreSQL |
| `APP_DB_HEALTHCHECK_TIMEOUT_SEC` | `2` | Общий срок проверки готовности БД |

Ноль дополнительных соединений делает верхнюю границу пула явной.
Для демонстрации оставлены пять соединений. Замеры расчёта проходят через проверку
пользователя в БД; отдельная нагрузка на реестр и оптимизация DB-пула не измерялись.
Параметры таймаутов принимают дробные секунды. Statement timeout передаётся PostgreSQL
в миллисекундах; минимальное допустимое значение — `0.001` секунды.

Пароль хранится в настройках как Pydantic `SecretStr`: обычное строковое представление скрывает значение.
URL создаётся через SQLAlchemy `URL.create`, поэтому специальные символы пароля не склеиваются с частями URL.
`.env` игнорируется Git и не включается в Docker build context.
Настройки `POSTGRES_*` внутри контейнера БД формируются из `APP_DB_*`; отдельно вводить их не требуется.

Пользователь и имя БД в образе PostgreSQL используются при первом создании volume.
Изменение `.env` само по себе не переименует существующую БД и не сменит пароль внутри неё.
Для существующих данных такие изменения выполняются явно средствами PostgreSQL.

## Вычислительный пул

| Переменная | Default | Назначение |
| --- | --- | --- |
| `APP_COMPUTE_WORKERS` | `2` | Процессы расчёта на один HTTP-процесс; также предел допущенных работ |
| `APP_COMPUTE_MAX_POINTS` | `200000` | Максимум точек одного запроса, проверяется до передачи процессу |
| `APP_COMPUTE_CHUNK_POINTS` | `1024` | Размер порции времён для Skyfield/NumPy |
| `APP_COMPUTE_NUMERIC_THREADS` | `1` | Потоки BLAS/OpenMP на вычислительный процесс |
| `APP_COMPUTE_TIMEOUT_SEC` | `60` | Срок ожидания HTTP-результата, не срок убийства процесса |
| `APP_COMPUTE_START_TIMEOUT_SEC` | `30` | Срок запуска и прогрева всех вычислителей |
| `APP_COMPUTE_HEALTHCHECK_TIMEOUT_SEC` | `2` | Срок короткой пробы свободного вычислителя |

Порция 1024 выбрана по первым [замерам](benchmarks.md): увеличение до 4096 и 16384
повышало максимальную память без выигрыша времени. Весь ответ всё равно хранится в памяти.
Лимиты нужно проверять повторно при изменении данных, пакетов, оборудования или числа процессов.

У каждого HTTP-процесса собственный пул: всего `APP_HTTP_WORKERS × APP_COMPUTE_WORKERS`
вычислителей. Настройка потоков преобразуется в `OPENBLAS_NUM_THREADS`, `OMP_NUM_THREADS`,
`MKL_NUM_THREADS`, `VECLIB_MAXIMUM_THREADS` до импорта NumPy в процессе.
Увеличение сразу обоих множителей может привести к конкуренции за одни ядра и росту памяти.
Вычислительные работы не держат соединений или транзакций PostgreSQL.

При штатной остановке пул ждёт завершения начатых работ. `APP_SHUTDOWN_TIMEOUT_SEC`
ограничивает ожидание HTTP-задач Uvicorn, но не убивает численный процесс после истечения
`APP_COMPUTE_TIMEOUT_SEC`. Для принудительного окончания всего контейнера действует
также срок остановки Docker. Аварийно завершившийся пул требует перезапуска приложения.

## Ручные замеры

Эти настройки читает `poetry run poe benchmark`. В приложении они не используются.
`benchmarks/settings.py` читает окружение и `.env`; общая модель полей для настройки
и её снимка в отчёте находится в `models/pydantic/benchmarks.py`.
Compose передаёт их контейнеру `tests`, в котором также можно запустить benchmark.
Внутри Docker его адрес API установлен в `http://app:<APP_PORT>`, аналогично адресам БД.

| Переменная | Default | Назначение |
| --- | --- | --- |
| `APP_BENCH_MODE` | `http` | `http` — работающий API; `core` — прямой запуск ядра с подготовкой JSON |
| `APP_BENCH_USERNAME` | пустая строка | Существующий пользователь; обязателен для HTTP-режима |
| `APP_BENCH_PASSWORD` | пустая строка | Его пароль (`SecretStr`); обязателен для HTTP-режима |
| `APP_BENCH_BASE_URL` | `http://127.0.0.1:8000` | Адрес API для локального benchmark |
| `APP_BENCH_INPUT` | `examples/request-omm.json` | Зафиксированный запрос с элементами орбиты |
| `APP_BENCH_OUTPUT` | `artifacts/benchmark.json` | Путь JSON-отчёта |
| `APP_BENCH_REPETITIONS` | `5` | Число последовательных измерений каждого сценария |
| `APP_BENCH_CONCURRENCY` | `4` | Одновременные запросы с `APP_COMPUTE_MAX_POINTS` точками |
| `APP_BENCH_TIMEOUT_SEC` | `90` | Сетевой timeout клиента benchmark, с запасом к сроку ожидания API |
| `APP_BENCH_HEALTH_INTERVAL_SEC` | `0.05` | Пауза между парами live/ready во время HTTP-замера |

Логин и пароль исключены из JSON-отчётов через `Field(exclude=True)`.
В `.env.example` заполнены демонстрационные `testuser / test-password`, которые создаёт
`docker compose exec app python -m api.demo_user` или локальная задача `poetry run poe add-test-user`.
Benchmark выполняет один вход перед прогревом; время входа не входит в время расчётов.
Пользовательская квота применяется и к benchmark. При большом числе повторов `429`
отражается в отчёте; для измерения вычислений согласуйте конфигурацию лимита с числом запросов.

## Тестовая PostgreSQL

| Переменная | Default | Назначение |
| --- | --- | --- |
| `APP_TEST_DB_HOST` | `localhost` | Адрес тестовой БД для локального pytest |
| `APP_TEST_DB_PORT` | `55433` | Её отдельный опубликованный порт |
| `APP_TEST_DB_USER` | `orbits_test` | Отдельный пользователь |
| `APP_TEST_DB_PASSWORD` | `orbits_test` | Демонстрационный пароль тестового пользователя |
| `APP_TEST_DB_NAME` | `orbits_test` | Имя должно оканчиваться на `_test` |

Контейнер `tests` переопределяет тестовые хост и порт на `postgres-test:5432`.
Тесты читают именно `APP_TEST_DB_*` и явно передают эти реквизиты своему экземпляру приложения.
Настройки рабочей БД не становятся запасным источником реквизитов тестовой БД.

Тесты очищают таблицы `users` и `satellites` перед использованием и проверяют downgrade.
Рабочую БД или общую БД с ценными тестовыми данными указывать нельзя.

## Тестовый Redis

| Переменная | Default | Назначение |
| --- | --- | --- |
| `APP_TEST_REDIS_HOST` | `localhost` | Адрес отдельного `redis-test` |
| `APP_TEST_REDIS_PORT` | `56380` | Отдельный опубликованный порт |
| `APP_TEST_REDIS_PASSWORD` | `orbits_redis_test` | Демонстрационный пароль тестового Redis |

Compose устанавливает адрес `redis-test:6379`. Тесты явно выбирают логическую DB 15,
новый случайный префикс `test:<UUID>` для каждого приложения и отдельный тестовый секрет JWT.
Рабочие `APP_REDIS_*` и секрет не используются как запасной источник тестовой конфигурации.
`FLUSHALL` и `FLUSHDB` не выполняются; тестовые ключи удаляются по собственному сроку.

## Docker Compose и сборка

| Переменная | Default | Назначение |
| --- | --- | --- |
| `APP_DEPLOY_BIND_HOST` | `127.0.0.1` | Интерфейс публикации API, PostgreSQL и Redis, включая тестовые |
| `APP_DEPLOY_PYTHON_IMAGE` | `python:3.13.14-slim` | Базовый образ Python |
| `APP_DEPLOY_POSTGRES_IMAGE` | `postgres:16-alpine` | Образ PostgreSQL; проверяется ветка 16 |
| `APP_DEPLOY_REDIS_IMAGE` | `redis:8-alpine` | Образ Redis для приложения и тестов |
| `APP_DEPLOY_REDIS_MAX_MEMORY_BYTES` | `67108864` | Лимит данных рабочего Redis, 64 MiB; `noeviction` |
| `APP_DEPLOY_POETRY_VERSION` | `2.4.1` | Версия Poetry при сборке |
| `APP_DEPLOY_HEALTHCHECK_INTERVAL_SEC` | `5` | Интервал Docker healthcheck |
| `APP_DEPLOY_HEALTHCHECK_TIMEOUT_SEC` | `3` | Срок Docker healthcheck и его HTTP-запроса |
| `APP_DEPLOY_HEALTHCHECK_START_PERIOD_SEC` | `10` | Начальный период запуска healthcheck |
| `APP_DEPLOY_HEALTHCHECK_RETRIES` | `10` | Число неудач до статуса unhealthy |

Эта группа читается Compose. Только HTTP timeout healthcheck дополнительно передаётся контейнеру
приложения для его служебной команды. Python-модель настроек приложения не обязана знать параметры сборки.
`poetry.lock` фиксирует Python-пакеты; теги Docker-образов не являются фиксацией их digest.
Обновления образов следует проверять теми же тестами. Смена major PostgreSQL требует отдельной
процедуры переноса данных и не является обычным изменением `.env`.

Версия приложения, HTTP-маршруты, имена полей контрактов и идентификаторы миграций относятся
к версии программы, поэтому хранятся в коде и метаданных проекта.

## Пароли и токены

| Переменная | Default | Назначение |
| --- | --- | --- |
| `APP_AUTH_TOKEN_SECRET` | обязательна | Минимум 32 символа; `.env.example` содержит фиксированный ключ демонстрации |
| `APP_AUTH_TOKEN_TTL_SEC` | `900` | Срок доступа, 15 минут |
| `APP_AUTH_TOKEN_ISSUER` | `orbit-coordinate-service` | Проверяемый издатель JWT |
| `APP_AUTH_TOKEN_AUDIENCE` | `orbit-api` | Проверяемый получатель JWT |
| `APP_AUTH_PASSWORD_WORKERS` | `2` | Одновременные проверки пароля на HTTP-процесс |
| `APP_AUTH_PASSWORD_MEMORY_KIB` | `65536` | Память одной операции Argon2 в KiB (64 MiB) |
| `APP_AUTH_PASSWORD_TIME_COST` | `3` | Число проходов Argon2 |
| `APP_AUTH_PASSWORD_PARALLELISM` | `2` | Число полос Argon2; память должна быть минимум `8 × parallelism` KiB |

Алгоритм HS256 закреплён контрактом программы. Секрет общий для всех HTTP-процессов
и экземпляров одного окружения. Пароли и секреты в настройках скрыты через `SecretStr`;
сам `.env` содержит открытые значения и остаётся локальным.
Дополнительные причины и порядок отзыва доступа: [доступ](access.md).

## Redis и частота запросов

| Переменная | Default | Назначение |
| --- | --- | --- |
| `APP_REDIS_HOST` | `localhost` | Compose переопределяет на `redis` |
| `APP_REDIS_PORT` | `56379` | Снаружи Docker; внутри Compose используется `6379` |
| `APP_REDIS_DB` | `0` | Логическая БД, 0–15 |
| `APP_REDIS_PASSWORD` | `orbits_redis` | Демонстрационный пароль Redis |
| `APP_REDIS_KEY_PREFIX` | `orbits` | Пространство ключей, общее для экземпляров одного окружения |
| `APP_REDIS_MAX_CONNECTIONS` | `20` | Максимум соединений на HTTP-процесс |
| `APP_REDIS_CONNECT_TIMEOUT_SEC` | `2` | Установление соединения |
| `APP_REDIS_SOCKET_TIMEOUT_SEC` | `2` | Сетевой timeout и общий deadline проверки лимита |
| `APP_REDIS_HEALTHCHECK_TIMEOUT_SEC` | `2` | Общий deadline проверки доступности Redis |
| `APP_RATE_LIMIT_USER_REQUESTS` | `60` | Защищённые запросы на ID пользователя за окно |
| `APP_RATE_LIMIT_USER_WINDOW_SEC` | `60` | Продолжительность пользовательского окна |
| `APP_RATE_LIMIT_LOGIN_REQUESTS` | `10` | Попытки входа на IP за окно |
| `APP_RATE_LIMIT_LOGIN_WINDOW_SEC` | `60` | Продолжительность окна входа |

Все экземпляры, разделяющие квоту, должны использовать одинаковые настройки окон и пределов.
Иначе итоговое поведение будет зависеть от того, какой экземпляр обработал запрос.
Счётчики не сохраняются на диск, окна начинаются с первого запроса, повторный запрос
не продлевает их. При отказе Redis или исчерпании его памяти защищённый запрос получает `503`.
